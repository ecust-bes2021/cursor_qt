---

## 📋 快速开始（3步启动）

### 第一次使用（一次性设置，10分钟）

1. **让AI生成文档骨架**
   ```
   请帮我初始化AI协作文档：
   1. 扫描项目结构，生成 .ai/MAP.md（代码地图）
   2. 创建 .ai/TASK.md（任务追踪模板）
   3. 创建 .ai/RULES.md（编码规范模板）
   ```

2. **人工补充关键信息**（见下方"人机分工"）
   - 在 MAP.md 中标注 🔒 稳定模块
   - 在 MAP.md 中补充设计决策
   - 在 TASK.md 中填写当前任务

3. **开始使用**
   每次新对话使用标准开场白（见下方"对话模板"）

## 📁 文档体系说明

```
.ai/
├── README.md          # 本文件 - 使用指南
├── MAP.md             # 代码地图 - AI快速定位代码
├── TASK.md            # 任务追踪 - 记录开发进度
└── RULES.md           # 编码规范 - 保持代码一致性
```

### MAP.md - 代码地图（最重要）
**作用**：让AI不用"探索"项目，直接"知道"项目结构  
**内容**：
- 项目架构图
- 模块职责说明
- 关键设计决策
- 稳定代码标记（🔒）
- 数据流说明

### TASK.md - 任务追踪
**作用**：让AI知道"现在在做什么"、"什么已完成"  
**内容**：
- 当前正在进行的任务
- 已完成的功能（标记为稳定）
- 下一步计划

### RULES.md - 编码规范
**作用**：保持代码风格一致  
**内容**：
- 命名约定
- 文件组织规则
- 设计模式约定
- 禁止事项

## 🤝 人机分工（重要！）

### ✅ AI自动生成的部分

| 内容 | 说明 | 如何生成 |
|------|------|---------|
| 项目目录结构 | 扫描文件系统 | `请扫描项目生成目录树` |
| 技术栈识别 | 分析配置文件 | `请识别项目使用的技术栈` |
| 代码地图骨架 | 列出文件和模块 | `请生成代码地图骨架` |
| 函数/类清单 | 代码静态分析 | `请列出主要的类和函数` |

### ⚠️ 必须人工补充的部分

| 内容 | 为什么AI做不了 | 示例 |
|------|---------------|------|
| 设计决策的"为什么" | AI不知道业务背景 | "为什么用MVC？因为..." |
| 稳定代码标记 | AI不知道哪些已测试 | "🔒 core/engine.py 已稳定" |
| 当前开发重点 | AI不知道优先级 | "本周重点：导出功能" |
| 业务需求 | AI不知道用户需求 | "需要支持1000+并发" |
| 模块依赖关系 | 隐式依赖AI看不到 | "UI层依赖Service层" |
| 禁止修改的区域 | AI不知道历史问题 | "不要动auth模块，有坑" |

## 🎯 效率提升的关键技巧

### 1. 用"地图"代替"探索"
❌ "帮我找到处理用户登录的代码"  
✅ "查看 `.ai/MAP.md`，登录逻辑在 `services/auth/login.py`"

### 2. 用"标记"代替"提醒"
❌ 每次都说"别改core模块"  
✅ 在 MAP.md 中标注 "🔒 core/ - 核心引擎，已稳定"

### 3. 用"参考"代替"描述"
❌ "我想要一个导出功能，格式是..."  
✅ "参考 `export/excel_exporter.py` 实现PDF导出"

### 4. 用"约束"代替"修复"
❌ AI改错了再让它改回来  
✅ 提前在对话中明确"不要修改X"

### 5. 用"状态"代替"记忆"
❌ 依赖AI记住上次做了什么  
✅ 在 TASK.md 中记录进度

## ❓ 常见问题

**Q: 这些文档会过时吗？**  
A: MAP.md 相对稳定，TASK.md 需要经常更新。建议每次对话结束让AI更新。

**Q: 小项目也需要吗？**  
A: 小项目只需要一个简化的 MAP.md 即可，记录基本结构和约束。

**Q: 团队协作怎么办？**

### RULES.md 模板

```markdown
# 编码规范

## 命名约定
[AI可以从现有代码学习，👤 人工确认]

- **类名**：PascalCase (例：`UserService`)
- **函数名**：snake_case (例：`get_user_by_id`)
- **常量**：UPPER_CASE (例：`MAX_RETRY_COUNT`)
- **私有方法**：`_method_name`

## 文件组织
[👤 人工定义规则]

- 每个类一个文件
- 文件名与类名对应：`UserService` → `user_service.py`
- 测试文件：`test_*.py`

## 设计模式约定
[👤 人工说明 - AI需要知道的模式]

- **服务层**：所有业务逻辑必须在 `services/` 中
- **信号槽**：模块间通信使用Qt信号，不直接调用
- **单例模式**：数据库连接使用单例

## 代码风格
[AI可以从现有代码学习]

- 使用类型注解
- 文档字符串使用Google风格
- 最大行长：100字符

## 禁止事项
[👤 人工定义 - 这很重要！]

- ❌ 不要在UI层直接操作数据库
- ❌ 不要使用全局变量（除了配置）
- ❌ 不要修改第三方库的代码
- ❌ 不要在循环中执行数据库查询

## 错误处理
[👤 人工定义规范]

- 使用自定义异常类
- 不要捕获所有异常 (`except Exception`)
- 记录错误日志

## 测试规范
[👤 人工定义]

- 每个功能必须有单元测试
- 测试覆盖率 > 80%
- 使用 pytest 框架
```
